# Idea Bot: создание новой темы по явной просьбе

Дата: 2026-10-10. Статус: ждёт вычитки Некита.

## 1. Контекст и проблема

Темы в `Творческие идеи.canvas` жёстко заданы списком `config/themes.yaml` (`ideabot/brain.py`: «theme: строго одна из перечисленных тем»). Если Некит текстом просит бота завести новую тему/подхолст («Создай новый подхолст "Идеи для НАП" и внеси под него...»), Claude не может вернуть тему вне списка — `validate()` в `brain.py` подменяет её на fallback-тему («Разное»), просьба молча игнорируется.

Обнаружено на живом прогоне (задача 11 из `docs/plans/2026-09-26-idea-bot.md`), зафиксировано в `HANDOFF.md`.

## 2. Критерии успеха

- Если текст явно просит создать новую тему, бот это распознаёт и показывает карточку с выбором, а не молча кладёт идею в fallback-тему.
- Новая тема создаётся только после подтверждения кнопкой в Telegram, никогда автоматически.
- Если предложенное название совпадает с уже существующей темой — используется существующая без лишнего диалога.
- Если похожая тема есть, но не совпадает точно — бот предлагает обе опции: создать новую или использовать похожую.
- Если Некит отказывается создавать новую тему — бот даёт выбрать любую существующую тему из списка.
- Вне явной просьбы создать тему поведение бота не меняется: Claude не предлагает новые темы по догадке о несовпадении.

## 3. Решения из брейншторма

| # | Решение |
|---|---|
| Где живёт новая тема | Новая группа в существующем `Творческие идеи.canvas`, как и остальные темы. Новый L1-холст не создаётся |
| Триггер | Только явная текстовая просьба создать тему/подхолст. Никогда по эвристике «идея не подходит ни под одну тему» |
| Похожая тема найдена | Бот показывает обе кнопки: создать новую / использовать похожую |
| Отказ создавать | Бот показывает список всех существующих тем для ручного выбора |
| Разбиение одного сообщения на несколько идей | Вне скоупа, разовый случай, архитектуру под это не меняем |

## 4. Поток

```
Некит: "Создай тему X и занеси идею Y"
        │
        ▼
brain.analyze() возвращает Analysis с new_theme = {name: "X", closest_existing: "Нячанг" | null}
        │
        ▼
pipeline: a.new_theme не пусто, не дубликат, не append
        │
        ▼
status = "await_theme", карточка в Telegram:
  ┌─────────────────────────────────────┐
  │ 🆕 Хочешь завести тему «X»?          │
  │ Похоже на «Нячанг» — положить туда?  │
  │                                       │
  │ [🆕 Создать «X»] [📂 Использовать «Нячанг»] │
  │ [📋 Другая тема]                     │
  └─────────────────────────────────────┘
        │                    │                      │
        ▼                    ▼                      ▼
  resolve_theme_create  resolve_theme_existing  список тем кнопками →
  (дописывает          (a.theme = "Нячанг",     resolve_theme_existing
   config/themes.yaml,  write())                 с выбранным именем
   s.themes.append,
   a.theme = "X",
   write())
```

Если `closest_existing` равен `null` (похожей темы нет вовсе), кнопка «Использовать «Y»» не показывается — только «Создать» и «Другая тема».

Если нормализация в `validate()` обнаруживает, что `new_theme.name` **точно** совпадает с уже существующей темой — `await_theme` не наступает вообще, `a.theme` сразу выставляется в неё, идея пишется как обычно.

## 5. Изменения по файлам

### `ideabot/brain.py`

- В `SYSTEM`-промпт добавляется правило: `new_theme` заполняется только если текст явно просит создать новую тему/подхолст (явные формулировки: «заведи тему», «создай подхолст», «новая категория» и подобные), никогда из-за того, что идея просто не вписывается ни в одну существующую тему.
- `ANALYSIS_SCHEMA` получает необязательное поле:
  ```python
  "new_theme": {"type": ["object", "null"], "properties": {
      "name": {"type": "string"},
      "closest_existing": {"type": ["string", "null"]},
  }}
  ```
- `validate()`: если `new_theme.name` (после strip) совпадает с элементом `s.themes` — использовать эту тему как `a.theme`, `new_theme` не передавать дальше. Если `closest_existing` не входит в `s.themes` — обнулить его. Итоговое поле на `Analysis` — `new_theme: dict | None` (или `None`, если после нормализации стало неактуально).

### `ideabot/models.py`

- `Analysis` получает поле `new_theme: dict | None = None` (`{"name": str, "closest_existing": str | None}`), сериализуется как обычно через `asdict`/`from_dict`.

### `ideabot/config_themes.py` (новый файл)

- `add_theme(s: Settings, name: str) -> None`: читает `config/themes.yaml`, вставляет `name` перед fallback-темой (если её там ещё нет), пишет файл атомарно через `yaml.safe_dump(..., allow_unicode=True, default_flow_style=False)`, затем `s.themes.insert(len(s.themes) - 1, name)` — мутирует список в памяти процесса в том же порядке, что и в файле (чтобы `themes.index()` в `canvas.py` работал одинаково что в проде, что после рестарта).
- Защищается тем же `pipeline.vault_lock`, что и запись в canvas (вызывается изнутри pipeline под локом).

### `ideabot/pipeline.py`

- `WRITABLE_STATUSES` дополняется `"await_theme"` — чтобы ретраи и общая логика «идея не теряется» подхватывали зависшие на этом статусе идеи так же, как остальные.
- В `process()`: после успешного `brain.analyze()`, если не дубликат (`a.duplicate_of` пуст) и `a.new_theme` не пусто — `status = "await_theme"`, `notifier.refresh`, return (не писать).
- В `resolve_duplicate()`: если результат — режим `"new"` (не `"append"`) и у `a.new_theme` что-то есть, тот же переход в `await_theme` вместо немедленного `write()`. Через небольшой общий хелпер `_route_new(idea_id, a)`, вызываемый из обоих мест.
- Новые методы:
  - `resolve_theme_create(idea_id)`: берёт `a.new_theme["name"]`, зовёт `config_themes.add_theme(s, name)` под `vault_lock`, `a.theme = name`, `a.new_theme = None`, сохраняет analysis, зовёт `write(idea_id)`.
  - `resolve_theme_existing(idea_id, theme_name)`: `a.theme = theme_name`, `a.new_theme = None`, сохраняет analysis, зовёт `write(idea_id)`. Используется и для кнопки «Использовать «Y»», и для выбора из полного списка тем.

### `ideabot/cards.py`

- `card_text()`: новая ветка для статуса `await_theme` — текст вида `🆕 Завести тему «{name}»?` + (если есть closest) `Похоже на «{closest}» — положить туда?`.
- `card_kb()`: новая ветка, кнопки `nt:{id}:c` (создать), `nt:{id}:u` (использовать closest, только если он есть), `nt:{id}:o` (другая тема → открывает список).
- Новая функция `theme_kb(idea_id, themes)`: список всех `s.themes` кнопками, без мультивыбора — каждая кнопка сразу коммитит (`th:{id}:{n}`), плюс «✖️ Назад» (`bk2:{id}`, возвращает карточку `await_theme`).

### `ideabot/bot.py`

- Новые обработчики callback'ов:
  - `nt:{id}:c` → `pipeline.spawn(pipeline.resolve_theme_create(id))`.
  - `nt:{id}:u` → `pipeline.spawn(pipeline.resolve_theme_existing(id, a.new_theme["closest_existing"]))`.
  - `nt:{id}:o` → показывает `theme_kb(id, sorted(s.themes))` через `edit_reply_markup`, без изменения статуса в БД (аналог `change()` для холстов).
  - `th:{id}:{n}` → `pipeline.spawn(pipeline.resolve_theme_existing(id, picked_theme_name))`.
  - `bk2:{id}` → `notifier.refresh(id)` (вернуть карточку `await_theme`).
- Хранение выбора темы между показом списка и тапом — по тому же паттерну `picks`, что уже используется для холстов (`ch:`/`tg:`/`ok:`), но здесь одиночный выбор, так что состояние можно не держать в `picks`: кнопки `th:{id}:{n}` прямо кодируют индекс темы, достаточно `sorted(s.themes)[n]` в обработчике — не нужен промежуточный словарь.

## 6. Конкурентность и надёжность

- Запись в `config/themes.yaml` и последующая запись в canvas идут под одним и тем же `pipeline.vault_lock`, что и остальные операции с vault — не может возникнуть гонки между параллельными идеями.
- `await_dup` уже входит в `WRITABLE_STATUSES` по конкретной причине: `resolve_duplicate()` зовёт `write()`, не поменяв статус заранее, и guard в начале `write()` (`if idea.status not in WRITABLE_STATUSES: return`) иначе бы его отбросил. `await_theme` добавляется в `WRITABLE_STATUSES` ровно по той же причине — `resolve_theme_create`/`resolve_theme_existing` зовут `write()`, пока статус ещё `"await_theme"`. Сам по себе `await_theme`, как и `await_dup`, не трогается фоновым `retry_loop()` (тот перебирает только `write_failed`) — идея висит в `await_theme` до явного решения Некита, это ожидаемо.
- Если `add_theme()` упадёт (например, YAML стал невалидным руками) — ошибка оборачивается в `BrainError`-подобный путь: `resolve_theme_create` ловит исключение, откатывается на статус `write_failed` с текстом ошибки, карточка показывает «не смог создать тему, попробую позже» — по аналогии с уже существующей обработкой `write_failed` в пайплайне.

## 8. Вне скоупа

- Разбиение одного сообщения на несколько отдельных идей — отдельная будущая фича, не часть этой задачи.
- Переименование или удаление тем через бота.
- Перенос темы в отдельный L2-холст (сейчас и после этой фичи темы остаются группами внутри `Творческие идеи.canvas`).
